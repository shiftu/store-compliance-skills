# 判定口径与防误报

适用于 Apple App Store（`rules/apple_rules.json`）。Play 版见 play-store-compliance 的同名文件，规则库换成 `play_rules.json`。

## 1. 四个取值，只能选一个

| 取值 | 什么时候用 | 反例（错用） |
|---|---|---|
| `符合` | 有正面证据说明该义务已落实，或该禁止条款外部未见违反证据 | 把「没有这个功能」写成符合 |
| `不符合` | 有正面证据说明违反（`find`），或「该有的东西确已缺失」且该缺失本身即违反（`absent` + `absence_only_violation`） | 用「没找到」当违反 |
| `无法从外部判断` | 义务本身要看应用内、安装包、商店后台，或需要图像/实机才能判 | 因为懒得判就把整条丢这里 |
| `不适用` | 条款前提在本款应用上不成立（无该功能 / 分类不符 / 分级已覆盖） | 用「符合」代替「不适用」 |

「不适用」和「符合」是两件事：前者是「这条管不到它」，后者是「它做到了」。混用会让「符合」的数字失去意义。

## 2. 三层可观测性（决定这条能不能从外部定论）

| 层 | 拿到什么 | 典型条目 |
|---|---|---|
| `public_listing` / `policy_page` / `policy_docs` | 商店页 HTML、隐私政策正文、条款正文、Data safety 页 | 标题长度、分级取值、隐私政策是否 200、交易者信息、IAP 申报 |
| `binary_only` | 安装包：静态扫描、字符串、权限、SDK 清单 | 隐藏功能、第三方 AI 供应商实际调用、埋点 |
| `human_only` / `console` | 实机操作或 App Store Connect / Play Console 后台 | 弹窗时机与同意记录、年龄门、付费墙、Data safety 表单填写、截图是否真实 |

一条义务同时横跨两层时（例：「公开页是否声明年龄限制」可查 vs 「应用内年龄门是否落地」不可查），拆成两层写 `layers[]`，各自给结论与说明；**不要因为深层判不了，就把整条降级成「无法判断」**——那会把已经确认的违规一起丢掉。

## 3. route：谁给结论

- `script`：`fetch_listing.py` 解析字段后可直接定论（分级数值、链接 HTTP 状态、标题字符数、交易者块有无、IAP 申报）。这些条目模型不重判，直接沿用 `script_verdicts.json`。
- `llm`：模型读 `_raw` 文本按 `verify` 步骤判。证据必须逐字。
- `human_only`：外部无法定论，一律 `无法从外部判断`，并在 `verified_by` 写清找谁要。

## 4. 防误报（这几条踩过）

1. **「App 隐私」区块的数据类别不是宣称。** `Diagnostics`、`Crash Data` 是苹果的隐私标签分类，不能当成「医疗诊断」证据。声明类条款（医疗、博彩、强制评分）只看 `_raw/<slug>_description.txt`（应用自述）。
2. **页面渲染丢行 ≠ 缺失。** 服务端渲染的商店页可能整行不出现（如 `App Support`）。这类差异判「无法从外部判断 / 中」，不判「不符合」。
3. **分级取值本身不是合规证明。** 分级是答案的产物；问卷是否如实填写只有后台可见。看到 `18+` 只能支持「分级经填过」，不能支持「内容确实够 18+」。
4. **一个 URL 抓到 200 不等于链接合规。** 还要看：是否本 App 自有域名、是否 PDF、是否点名本 App。三项缺一即降置信度。
5. **评论/竞品/论坛只能当触发信号。** 商店评论说「免费是假的」可以支持「值得实机看付费墙」，但不能作为 `find` 证据。
6. **不要拿描述文本代替截图判读。** `2.3.3`/`2.3.8`/`2.3.14` 依赖图片像素，没图片就判「无法从外部判断」。
7. **同一条款在不同店面的表现不同。** EU 店面缺交易者块是 DSA 问题，US 店面不看这个；判 `ASRG-DSA-TRADER` 时以 EU 页面为准并在证据里写明店面。

## 5. 置信度

| 值 | 标准 |
|---|---|
| `高` | 原文/字段明确，机械可复核（HTTP 状态、字符数、字段有无、逐字句） |
| `中` | 需要一步推论，或依赖页面渲染/第三方页面完整性 |
| `低` | 间接推断、只有部分信号（如仅有评论线索） |

## 6. 报告里不许出现的句子

「会通过」「会被拒」「大概率过」「建议直接上架」「审核通过率」。报告只写：哪条条款、什么证据、条款规定的后果、怎么改。`check_run.py` 会扫这些词。
